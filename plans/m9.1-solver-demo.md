# M9.1 — Solver demo MVP

Detailed plan for the open block in `LOG.md`. Branch already cut: `m9.1-solver-demo` (HEAD `1152989`).

## Context

We have a usable trained 3x3 ValueNet — `experiments/davi-3x3/runs/20260508T084940Z_ln_kmax30_100k/net_final.pt`, which under `fast_kmax30` eval reaches d=14=0.98 and d=30=0.76 at beam width=256 BF16. M8 is closed; M9 begins. The first deliverable is the simplest thing that makes the trained network *visible*: scramble a cube → render it 2D → solve it via the network → step through the solution.

Upstream architectural decisions are locked in `plans/m9-ui.md`:
- FastAPI Python backend; loads model in lifespan; warms one solve before reporting healthy.
- Vite + React + TS + pnpm frontend; cubing.js installed (mostly for M9.2 `<twisty-player>`; M9.1 doesn't strictly need it).
- 54-char facelet string is the on-the-wire cube state representation.
- Singmaster QTM move strings (`R`, `R'`, `U`, ...) — already what `src/rubik/notation/moves.py:MOVE_STRINGS` emits.

Below is the breakdown into atomic commits. Each commit must leave tests green. Wave order is sequential — each commit depends on the previous.

## Sticker-layout facts (confirmed)

- Internal state `(54,) int8`: face order `(U, L, F, R, B, D)` (`spec.faces` in `src/rubik/cube/spec.py:41`), 9 stickers per face, **row-major top-left → bottom-right within each face** (canonical statement at `src/rubik/oracle/cubie.py:412–419`; renderer also at `src/rubik/viz/svg.py:12–14`). Per-face viewing orientations pinned at `src/rubik/oracle/cubie.py:151–158` match kociemba's standard convention (verified face-by-face).
- Kociemba 54-char facelet string: face order `URFDLB`, row-major within each face, characters `U/R/F/D/L/B` denoting the face the sticker's *color* belongs to. Conversion is therefore (a) face-block permutation `(0,1,2,3,4,5) → (0,3,2,1,4,5)` (i.e. internal index → kociemba index) and (b) color-int → letter map using kociemba's face order.
- No existing facelet/kociemba converter in repo (verified by grep).

## Atomic commits

### 1. `facelet` — kociemba ↔ internal converter

Pure functions in a new module. No web/server dependencies.

**Files**
- `src/rubik/notation/facelet.py` — `state_to_facelet(state, spec) -> str`, `facelet_to_state(facelet, spec) -> torch.Tensor`. Module docstring lays out the convention with the same precision as `notation/moves.py` (face order, within-face order, color-letter map).
- `tests/notation/test_facelet.py` — solved-state matches `"UUUUUUUUU" + "RRRRRRRRR" + "FFFFFFFFF" + "DDDDDDDDD" + "LLLLLLLLL" + "BBBBBBBBB"`; round-trip on N=64 random scrambles via `random_scrambles` (use `torch.Generator().manual_seed(0)` per local convention, e.g. `tests/cube/test_apply_all_moves.py:30–37`); validation errors on length-mismatch and unknown-character inputs; both 2x2 and 3x3 specs round-trip.

**Acceptance.** `uv run pytest tests/notation/test_facelet.py` green; `uv run ruff check` clean.

### 3. `server-real-wiring` — model load + warmup + real handlers

Replace stubs.

**Files (modify)**
- `src/rubik/server/inference.py` —
  - `load_model(run_dir: Path) -> tuple[ValueNet, dict]`: reads sibling `config.yaml` for `body_widths`, `n_residual_blocks`, `normalization`; instantiates `ValueNet(CUBE_3X3, ...)`; loads bundle (preferring `ckpt["net_state"]` per `scripts/beam_eval_model.py:91–103`); moves to MPS; `.eval()`.   - `scramble_facelet(spec, length, seed) -> tuple[str, list[str]]`: wraps `random_scrambles` (`src/rubik/cube/env.py:209`); converts state via `state_to_facelet` and move indices via `move_to_str` (`src/rubik/notation/moves.py:18`).

- `src/rubik/server/app.py` — lifespan now calls `load_model(...)` (path from `RUBIK_MODEL_PATH` env var, default `experiments/davi-3x3/runs/20260508T084940Z_ln_kmax30_100k/net_final.pt`), runs ONE warmup `solve_facelet` from a length-5 scramble (catches MPS first-kernel-compile cost), then sets `warmup_done=True`. Endpoints call into `inference.py`.

**Tests**

## Risk register (carried from `plans/m9-ui.md` + new)

1. **MPS first-solve compile cost** — handled by lifespan warmup (commit 3).
2. **CORS in dev** — handled by `fastapi.middleware.cors` allowlist (commit 2). Vite proxy in commit 4 also sidesteps it.
3. **Beam latency at width=256, length=20** — should be sub-second from earlier eval data; if it isn't, we'll discover in commit 7's smoke and address before closing.
4. **cubing.js ESM under Vite** — install in commit 4 but don't rely on it for move application (commit 7 uses our own codegen). cubing.js becomes load-bearing only at M9.2.
5. **Codegen drift** — if internal move tables ever change, the committed `faceletMoves.ts` diverges. Mitigation: `test_facelet_moves_codegen.py` re-runs the script and snapshot-compares.
