# v0.1.0 — `ln_kmax30_100k` ValueNet (prerelease)

> Best 3x3 ValueNet trained on this hardware so far. Not converged at depth — d=14 is saturated, d=20-30 are still climbing. Released as a snapshot of project state, not a finished artifact.

## What's in the box

- `net_final.pt` — 234 MB. PyTorch checkpoint bundle for a 3x3 ValueNet, step 100,000 of a warm-started two-phase training run. Contains `net_state`, `target_net_state`, `optimizer_state`, plus `step`, `wall_time_seconds`, and `wandb_run_id` provenance fields.
- `config.yaml` — frozen training config for the 100k continuation phase (architecture + optimizer + scramble curriculum, all earned values).

## What it's good / not good at

- **Good at:** length≤14 random-walk scrambles via beam-256+ search (≥98% solve rate). The expected use case for a 3x3 ValueNet at this stage of training.
- **Mid:** length-15-25 walks (70-85%).
- **Limited:** length-30 walks (76% — pushing the limit of the model's effective depth at this n_steps).
- **Don't use greedy.** Greedy decoding at deep V* is near-zero on every checkpoint we've trained — beam search is what extracts value from this network. Width-256 BF16 is the production default.

## Loading

```python
# Repo: https://github.com/jgriffin/rubik @ v0.1.0
import torch
from rubik.model.network import ValueNet
from rubik.cube.spec import CUBE_3X3

bundle = torch.load("net_final.pt", map_location="cpu", weights_only=True)
net = ValueNet(
    spec=CUBE_3X3,
    body_widths=(5120, 1024),
    n_residual_blocks=4,
    normalization="ln",
)
net.load_state_dict(bundle["net_state"])
net.eval()

# bundle also carries:
#   bundle["target_net_state"]    — DAVI target network state_dict
#   bundle["optimizer_state"]     — Adam optimizer state (for resuming training)
#   bundle["step"]                — 100000
#   bundle["wall_time_seconds"]   — total training wall-clock
#   bundle["wandb_run_id"]        — "xfn7v2q2" (phase 2)
```
